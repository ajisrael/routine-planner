Category management — design review

Pick categories from a searchable dialog in the task form · create categories on the fly · manage them all from the Tasks tab.

Where we are today

task form

backend

so…

This is a pure frontend feature — no schema or API work needed. Deleting a category keeps its tasks; they fall back to “No category” (schema ON DELETE SET NULL).

A · Task form → “Choose category” dialog

The task form's category select becomes a button showing the current pick. It opens this dialog: search filters the list, checkboxes pick, “＋ Add new” creates a category that is selected by default and removable (✕) until you Apply. Cancel discards; Apply commits.

Behavior decisions baked into the mockups

  • Add in dialog = created immediately (POST /api/categories) so it also appears on the other device and in filters right away; Apply only assigns it to the task.
  • ✕ in dialog deletes only categories created in this dialog session (never seeded/existing ones) — safety against typos.
  • Delete in manager works on any category; tasks using it fall back to “No category” (never blocked).
  • Live sync: creates/deletes broadcast over the socket, so the picker on the other device updates instantly.
  • The 5 seeded defaults are ordinary rows — fully deletable in the manager.
  • Category colors stay data-driven; event blocks, chips and filters keep reading them from the table.
